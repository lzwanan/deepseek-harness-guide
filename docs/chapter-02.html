第 2 章 · turn 与 step — 2.1

一次请求里到底发生了什么

把一次模型调用拆开看，其实是四段固定的动作。它们串成一个循环，循环转几圈，取决于模型要不要动手。

管线上的四个站点就是一次请求要经过的四段。点站点可以跳到那一刻；拖动进度条可以来回看；鼠标停在这张图上按空格能暂停。

这一节只要记住三行
  1. 一次 step 固定四段：取输入 → 装配 prompt → 流式请求 → 执行 / 收尾。
  2. 四段走完不等于结束。要动手就回到 loop 再来一圈，不动手才写 step/end。
  3. 每个 step 都会重新装配一次 prompt，所以历史越长，这一步越贵。
自测模型在一次回复里既说了一句话、又要调用工具，会因此多花一次请求吗？

不会。一次请求可以同时产出文本和工具调用。工具执行完，结果被塞回上下文，才进入下一个 step —— 也就是说，多花的那次请求来自「把工具结果再问一遍」，不是来自「同时说了话」。

一个回合，可以有零到多次请求

很多资料把「一问一答」说成一个回合，这不准确。一个 turn 从你按下回车开始，到「没有更多要做的了」结束；中间每转一圈就是一个 step，每圈都是一次独立的模型请求。所以模型连着调三次工具，仍然只算一个回合里的三步。

时间从上往下走：每一条箭头是一次说话，箭头的方向就是「谁对谁」。五次往返被左侧括号分成三段——三个 step，一个 turn。第 3 步没有工具要跑，循环才找到出口。点左边的 STEP 1 / 2 / 3 可以直接跳过去，进度条上的两道细刻就是这三段的分界。

这一节只要记住三行
  1. 一个 turn 从按下回车开始，到 turn/end 结束；中间可以有 0 到 N 个 step。
  2. 每次工具调用都要把结果送回模型、再请求一次，所以「做了三件事」是三次请求、一个回合。
  3. 所有往返都落在同一条日志里。turn 是日志上的一个片段，不是内存里的一个对象。
自测模型连着调了三次工具，用户看到的是几轮问答？

一轮。三次工具 = 三个 step = 一个 turn。用户只发了一条消息，也只会收到一条最终回复； 中间那三次往返是他看不见的，但全部记在日志里。

什么时候算结束

循环的出口只有一个：本次请求没有要求任何 工具，并且队列里没有新的用户输入。两个条件同时满足，才写 turn/end。少写一个，turn 就会提前关闭，后续消息会被当成新的回合。

packages/core/agent-loop

turn/start
  loop:  inbox/claimed → agent/pre-step → step/start → agent/request
         ├ 要求工具 → ctx.tools.execute() → 回到 loop
         └ 不要求   → step/end          → 结束本 turn
turn/end
这一节只要记住三行
  1. 出口只有一个：本次没有工具要跑，并且队列里没有新输入。
  2. 条件判断错了不会报错，只会表现成「消息串台」或「回合一直不结束」。
  3. 入口在 packages/core/agent-loop，搜 turn/end 就能顺着读完一次循环。
自测「循环的出口只有一个」——具体是哪两个条件？

① 本次请求没有要求任何工具；② 队列里没有新的用户输入。两个条件同时满足才写 turn/end。少一个，turn 就不会正常关闭。
