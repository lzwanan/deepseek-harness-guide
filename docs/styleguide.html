01

三条原则

principles

前面四版被否掉的方案，问题都不在「不好看」，而在「看起来像生成的」。生成物的特征是均匀： 所有盒子同一个圆角、字号只差 1px、颜色只差 5% 明度。三条原则就是对均匀的三次反抗。

P.01

对比要极端，不要均匀

24px 的编号和 10px 的微标签出现在同一行。中间不设 14/15/16/17 这种只差 1px 的档位 —— 层级要能在一眼之内分开，而不是让读者去「感觉」。

P.02

细节必须是信息，不是装饰

刻度、索引、时间码、包路径、真实行数。删掉一个细节如果没人察觉少了信息，那它就是装饰， 应该删掉。

P.03

空间由网格组织，不由留白堆积

24px 点阵底、16px 图网格、1180 的版心。留白是网格算出来的结果， 不是「这里感觉该空一点」。

验收动作：把页面截图缩到 30%。还能看出「哪里是标题、哪里是标注、哪里是测量结果」，就成立； 如果糊成一片均匀的灰，就是均匀过头了。

02

色彩

color

只有一个强调色：一种仪器青。不是「主色 + 辅色 + 点缀色」的套装 —— 它只出现在三件事上：信号（数据在流动）、当前态（你在哪）、可点提示。一屏之内不超过三处。

面 / 墨 / 线

--bg-2—

--ink—
--ink-3—
--ink-4—
--line—

--line 分区块，--rule 分列表行，--hair 画最轻的描边（标签边、旁注线）。三级线三个用途，不按「看起来差不多」混用。 --ink-4 对比度约 2.8:1，只允许出现在 13px 以下的辅助文案里，不能承载正文。

信号色

--signal—
--signal-2—
--signal-bright—
--signal-soft—
--signal-wash—
--signal-line—

--signal 在白底约 5.9:1，可以承载正文级文字；--signal-2、--signal-bright 只做图形（描边、圆点、进度填充），不用于文字。强调色的配比目标是 92% 面 / 7% 墨 / 1% 信号 —— 一张截图里青色超过三处，就删掉两处。

观测窗：一套 class，两副面孔

--panel—
--panel-card—
--panel-line—
--panel-edge—
--panel-ink—
--panel-ink-3—
--panel-axis—

亮色主题下面板是图纸（浅灰底、刻度、深青信号），暗色主题下才是 屏幕（近黑底、荧光青）。这也是为什么 JS 里不允许出现任何色值 —— 换肤只改 CSS，一套代码两副面孔。

代码块

--deep—
--deep-2—
--deep-line—

全站唯一被允许的深色块。读者对「代码是深色」有预期，但没有任何预期要求动画面板也必须是黑的 —— 这正是第三版返工的原因。

03

字体

typography

两种字体，不引入第三种。拉丁用 Inter，中文落到 PingFang SC / Noto Sans SC， 代码用 JetBrains Mono。全站零衬线；等宽必须关掉连字 —— 读者会照着屏幕抄命令， -> 变成箭头就是在骗人。

角色 规格 用途与样例
Display clamp(31→46) / 1.12 / −0.035em / 600 让它动手的，是 harness。
章节 H1 clamp(27→34) / 1.32 / −0.028em / 600 一次请求里到底发生了什么
H2 20 / 1.5 / −0.018em / 600 什么时候算结束 H2 前面有一条 28px 的实线。它是节内可跳转的锚点，不是装饰。
Lede 17 / 1.78 / 0 / 400 · ink-2 把一次模型调用拆开看，其实是四段固定的动作。
正文 16 / 1.82 / 0 / 400 · ink-3 循环的出口只有一个：本次请求没有要求任何工具。
微标签 10 / 1.6 / +0.14em / uppercase · ink-4 fig.01 · step · 04 段动作
章节编号 24 / 1.15 / −0.03em / 300 02

图注 12 / 1.75 / 400 · ink-4 · 左侧 1px 线 点站点可以跳到那一刻；拖动进度条可以来回看。

字距是全站最便宜的「去 AI 味」手段：20px 以上的标题用负字距（−0.018 → −0.035em），微标签反过来用正字距（+0.14em）。生成出来的页面几乎从不调字距， 所以所有文字都像从同一个文本框里倒出来的。

代码块里只用一个字重（400）。要标关键行就用颜色（--signal-bright）， 不用加粗 —— 等宽字体加粗会糊成一团。

04

网格与版心

grid

版心 1180 切成三列：侧栏 232、正文列 740、目录 208。正文列里再扣掉左 56 / 右 64 的内边距， 实际行宽 620。所以 --measure: 660 是上限，不是承诺 —— 写作时按 620 算行数。

侧栏 232 56 正文 620 64 目录 208
0 1180 · layout 最大宽度

版心之外还有 28px 页边距，写在 .topbar__inner 和 .home 上，不在 .layout 里 —— 所以上面这条剖面从 0 量到 1180，不含页边距。

三套网格，各管一段

24px 点阵（body::before）：只在首屏 800px 内可见，是「图纸」的底噪， 不参与任何元素对齐。
16px 图网格（figures.js 的 S.step）：轴的起止点、节点、 刻度共用一套坐标。节点 x 必须是 16 的整数倍，否则那把尺子只是装饰。
8px 间距档：8 / 16 / 22 / 32 / 40 / 64 / 88。不新增档位 —— 宁可跳到 88，也不要发明 72。

16px 对齐的可视证据

第一版这张图是「看起来对齐」的：节点 x 是手填的 108/244/380/516，刻度从 62 起每 16 一格。 两套坐标互不相干，于是每个点都落在刻度之间。后来统一到同一套数字里， 主刻度正好压在节点上，圆环下面露出一截刻度针 —— 对齐关系才看得见。

05

组件

parts

下面每个样本都是线上的同一份 HTML + CSS，不是另画的示意图 —— 包括那个能拖动、能按空格暂停的观测窗。

标签 / 三档，只差用途不差装饰
FIG.01 4 节 待补 空格

微标签 10px / +0.14em；计数标签 9px 实线框，表示「这里有一个真实数字」； 「待补」同样是 9px，但用虚线框 —— 虚线在工程语言里就是未完成，一眼能分开数据与占位。 同一种信息不做两种长相；不同用途也不借用同一种长相。

术语提示 / 悬停、focus、点击都能开

一个 turn 从你按下回车开始，到「没有更多要做的了」结束。虚线是这条规则的唯一提示， 所以它必须比正文浅、比背景深 —— 看得见，但不打断阅读。

一条解释不超过 60 字，先中文后英文括号；向下优先弹出（遮后文比遮上文好，也不会挂在标题上）； 术语表里必须有同名词条，否则这条提示就是孤证。

目录行 / 编号是第一眼落点
目录 / index 7 章 · 28 节
  1. 02 turn 与 step 3 节 一次对话的完整生命周期。两处可交互动画。 →
  2. 03 Session 日志 4 节待补 只追加的事件流，决定了回放与迁移。 →

编号 24px / 300，标题 17px / 500，说明 13px。行与行之间只用 1px 底线，不用卡片。 可读的那一章常驻箭头并给编号上色 —— 只靠 hover 才出现的箭头，等于让读者猜哪一行是链接。

观测窗 / 全站唯一需要「仪器感」的地方

标题栏 34px：左边 FIG 编号、中间标题、右边呼吸灯。面板里三层信息 —— 图形、读白、控件 —— 各占一行，不叠在一起。图注写在面板外面，用左线旁注，因为它是给人读的， 不是仪器读数。

小结与自测 / 每节固定收尾
这一节只要记住三行
  1. 一次 step 固定四段：取输入 → 装配 prompt → 流式请求 → 执行 / 收尾。
  2. 四段走完不等于结束。要动手就回到 loop 再来一圈。
  3. 每个 step 都会重新装配一次 prompt，所以历史越长，这一步越贵。
自测模型既说了一句话、又要调用工具，会因此多花一次请求吗？

不会。一次请求可以同时产出文本和工具调用。多花的那次请求来自「把工具结果再问一遍」， 不是来自「同时说了话」。

小结固定三条，每条一个可验证的事实，不写「本节介绍了…」。自测只问一个问题， 答案必须是本节的关键判断，不是记忆题 —— 记不住的细节应该去查源码，不该靠自测背下来。

节导航 / 悬浮在视口右侧，不进正文流
↑目录 ↓2.2 悬停展开 →「2.2 · 一个回合可以有多次请求」

每节末尾没有「上一节 / 下一节」块。右侧目录本来就常驻， 再给一遍是把同一件事说两次，而且每节都出现一次，读起来处处被打断。 改成贴在视口右侧的两个 46 × 30 方块（视口 ≥ 1340 才显示，版心外要留出 78px）， 悬停展开小节名 —— 想跳的时候在，不想跳的时候不占版面。章尾仍保留 pager。

常驻面必须有字，不能只有箭头。两个上下箭头贴在滚动条旁边， 第一眼会被读成「页面滚动」，点下去却是跨小节跳转 —— 同一个手势两种结果，是最糟的歧义。 所以常驻面写「方向 + 节号」（↑ 目录 / ↓ 2.2），把「跳哪儿」提前说出来，悬停再补全标题。

06

页面结构

structure

每章同一副骨架。差异只允许出现在概念段之后 —— 读者靠骨架认路，靠差异理解内容。 

第 0X 章 / 0X.Y
├ eyebrow        第 0X 章 · 章名 — 0X.Y
├ h1             一句话说清这一节在讲什么（不是章名复读）
├ lede           为什么值得读，两行以内
├ figure.scope   FIG.0N · 标题           ← 概念讲完才出现
├ figcap         怎么用 / 怎么读 / 边界
├ h2 (可选)      再分一层时才有
├ pre.code       源码片段               ← 图之后才出现
├ recap          三行，每行一个可验证的事实
└ details.check  一个问题，答案是本节的关键判断

三条硬约束：一节只加一个新概念；图必须出现在概念之后、代码之前， 否则读者先看到现象却没有问题；图注必须回答「怎么用」， 而不是复述图里已经写着的字。

节与节之间没有分隔块：靠 H2 的 64px 上边距和前置的 28px 短线收尾，跳转交给右侧悬浮条。 正文流里只有内容，不放导航。

07

动效

motion

一条 0 → 1 的连续时间轴，每一帧重算位置、长度、透明度。不是「每三秒换一次边框颜色」—— 那是幻灯片，元素不移动、不生长，读者看不出因果。学习场景里可控比自动播放重要： 能暂停、能单步、能拖动、能改速、能点节点跳转。

0 STEP 1 STEP 2 STEP 3 t = 0.46 1
参数 值 为什么
时长 11–15s · 每图一档 够读完三行读白，又不至于等到不耐烦。
驱动 requestAnimationFrame 每帧重算几何，所以信号真的在流动，而不是切换状态。
缓动 easeOut / easeInOut 进场快、落位稳。CSS 侧用 --ease 一条曲线包全场。
起播 IntersectionObserver 0.4 进入视口才播，离开即停。后台标签页不该烧 CPU。
降级 prefers-reduced-motion 停在末帧而不是首帧 —— 末帧是完整的图，首帧是空的。
刻线 stepMarks = 相位起点 轨道上的细刻和 STEP 按钮用同一组 t 算，点按钮才会正好停在刻线上。
空格键 视线中心仲裁 多张图同时在视口里时，只作用于最靠近视线中心的那张。
窄屏 min-width 560 + 横滑 等比缩进 430px 的屏幕，9px 字只剩 6.9px，图就从说明退化成装饰。宁可让人滑一下。

几何约束：等效字号 = 设计字号 × 容器宽 ÷ viewBox 宽。620px 的容器里， 560 的 viewBox 让 10px 变成 11px；640 的 viewBox 只剩 9.7px。先定容器，再定 viewBox —— 反过来做的结果就是「设计稿上很清楚，页面上糊成一团」。

时序图必须竖排（时间向下），每条消息独占一行。横排会把五个标签挤进 620px 的一行里， 标签只能压到 9px，中英文都得砍掉一半 —— 第二版的泳道图看不懂，根因是布局，不是配色。

两个状态不能在同一帧重叠。「淡出」与「替换物淡入」交叠时， 正在消失的那行会透进新框里，看起来像文字重影而不是被替换。前一段结束后再起后一段， 中间留 0.04–0.06 的空档。

读白必须和屏幕上的事实一致。图里此刻只有五条事件，读白就不能说「八条里…」—— 哪怕整张图最终会有八条。读者不会替你把时间轴往后推。

08

文案

voice

语气是「同事在旁边指着源码讲」，不是「课程在宣布知识点」。判断标准只有一条： 这句话能不能被验证。能，就留下；不能，就是气氛。

要 不要
短句，一句一个动作 长句套从句，读完忘了主语
术语先中文，括号英文：回合（turn） 直接甩缩写：TURN、LLM、CTX
具体数字：4 段动作、84 行、3 处命中 「多种」「若干」「高效」「强大」
敢说「这里容易错」，并说错在哪一行 「让我们一起探索吧」
陈述句结尾，句号 感叹号、emoji、🚀
标题可以有一个比喻，正文第一段就把它翻译成机制 比喻一路铺到底，读者记住画面忘了机制

现成的例子：「模型只会吐字。让它动手的，是 harness。」前半句是比喻，后半句立刻把责任交回给具体的一层程序。 比喻负责让人想读，机制负责让人读懂 —— 两者都不能缺席，也不能互相顶替。

09

红线

never

每条都附了「为什么」。没有理由的禁令会在下一次迭代里被顺手破掉。

  • 跨色相渐变 —— 按钮、标题、边框都不许。唯一允许的渐变是顶部 2px 进度条， 同色系两端，因为它表示「已读比例」，这个渐变是有数据的。
  • 玻璃拟态与多重大阴影 —— 层级用 1px 线和底色区分。阴影一旦出现， 就得解释是什么在发光，而页面上没有任何东西在发光。
  • 紫蓝配色 —— 这是「AI 产品」最饱和的视觉符号。读者第一眼就会把页面归到生成物里， 后面的内容再准也没用。
  • 居中大标题 + 副标题 + 两个按钮的首屏 —— 落地页语法。本站首屏是左对齐标题、 一段说明、一张结构图。
  • 圆角 ≥ 8px —— 全站 2–3px。大圆角会把工程图变成 App 卡片，测量感立刻消失。
  • 字号只差 2px 的层级 —— 要么差 4px 以上，要么别分。差 2px 的层级读者分不出来， 只会觉得「有点乱」。
  • emoji 当图标 —— 跨平台渲染不一致，在技术语境里像占位符。
  • 卡片套卡片 —— 一个页面最多一层容器，第二层用线不用框。.scope 是唯一的例外，因为它是「仪器」，不是「卡片」。
  • 没有含义的编号 —— 01 / 02 / 03 必须对应章节、顺序或测量值。 纯装饰的序号是 AI 味最重的细节之一。
